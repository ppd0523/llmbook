# 독자 검증과 퇴고 기록

퇴고의 목적은 구조, 설명 순서, 학습성을 개선하는 것이다. 맞춤법과 문장 표현은 최종 교정 단계에서 다룬다. 퇴고 전에 독자 검증을 먼저 하고, 그 결과를 퇴고의 입력으로 쓴다.

## 1. 독자 검증

작성자는 본문에 없는 맥락까지 알고 있으므로 "본문만으로 풀린다"를 스스로 판정하기 어렵다. 작성에 참여하지 않은 검토자가 대상 독자의 입장에서 본문을 읽고 연습문제를 푼다.

- 검토자: 별도 서브에이전트 / 사람
- 검토자에게 준 정보: `01_scope.md`의 대상 독자·선행지식과 검토할 챕터 파일만 준다. `_work/`의 조사·초고·정답 기록은 주지 않는다.
- 검토 대상 챕터:
- 실습형 명령 실행 여부: (실행함 / 실행 불가와 그 이유)

검토자 지시:

1. 대상 독자가 아는 것만 안다고 가정하고 본문을 처음부터 읽는다.
2. 정의 없이 등장한 용어, 건너뛴 단계, 앞뒤가 안 맞는 설명이 나오면 위치와 함께 기록한다.
3. 연습문제와 과제를 본문만으로 풀고, 답을 정한 뒤에 정답·해설과 비교한다.
4. 실습형 단계는 실행할 수 있으면 실행해 기대 출력과 비교한다.

| 위치 | 막힌 지점 또는 오답 | 원인 | 조치 |
|---|---|---|---|
| | | 용어 미정의/단계 누락/선행지식 과대 가정/문제·정답 모호/정답 오류 | |

검토자의 오답이 본문의 설명 부족 때문인지, 문제나 정답의 오류 때문인지 구분한다. 정답 오류는 기술 오류이므로 `05_review.md`에도 기록한다.

## 4. 구조 점검

- [ ] 문제 제기가 학습 목표와 연결된다.
- [ ] 챕터 골격이 자료 유형에 맞다.
- [ ] 한 절 안에서 개념 설명과 단계 절차가 섞이지 않는다.
- [ ] 개념형이면 직관 예시가 핵심 개념보다 먼저 제공된다.
- [ ] 추상 설명 뒤에 구체 사례가 나온다.
- [ ] 섹션 순서가 개념 의존성과 맞는다.
- [ ] 새 용어가 설명보다 먼저 등장하지 않는다.
- [ ] 용어 설명이 다른 미정의 용어에 의존하지 않는다.
- [ ] 불필요한 우회 설명이 제거되었다.

## 5. 학습성 점검

- [ ] 학습목표와 본문이 대응한다.
- [ ] 각 핵심 개념 뒤에 예시가 있다.
- [ ] 추상적이거나 혼동하기 쉬운 새 용어에 예시, 반례 또는 비교가 있다.
- [ ] 추상 설명과 구체 사례가 연결된다.
- [ ] 독자 검증에서 기록한 막힌 지점과 오답을 처리했다.
- [ ] 모든 연습문제와 과제에 정답·해설 또는 기대 출력·검증 명령이 있다. 참조형 챕터는 제외한다.
- [ ] 실습형 단계마다 기대 출력이 있고, 흔한 실패에 알아보는 신호와 복구 방법이 있다.
- [ ] 흔한 오해와 실패 사례가 포함된다.
- [ ] 개념형이면 Worked Example과 직접 풀이 문제가 함께 배치된다.
