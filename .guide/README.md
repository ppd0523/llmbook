# 기술자료 작성 가이드

[루트 AGENTS.md](../AGENTS.md)에서 작업 종류를 먼저 선택한다. 이 폴더는 공통 지침과 템플릿을 보관한다. 실제 집필 기록은 대상 책의 `_work/`에 작성한다.

## 규칙을 찾는 곳

| 문서 | 담당 내용 |
|---|---|
| [PROCESS.md](PROCESS.md) | 적용 범위, 시작 조건, 단계 전환, 검증과 완료 기준 |
| [OUTPUTS.md](OUTPUTS.md) | 독자용 산출물 형식과 파일·폴더 배치 |
| [MARKDOWN_STYLE.md](MARKDOWN_STYLE.md) | 본문 구조, 용어, 수식, 코드, 링크 표기 |

규칙은 담당 문서에서 수정하고 다른 문서에서는 참조한다. 템플릿은 필요한 단계에서 읽으며, 해당하지 않는 항목은 생략하거나 사유를 적는다.

## 단계별 템플릿

| 템플릿 | 기록할 내용 |
|---|---|
| [01_scope.md](01_scope.md) | 독자, 목표, 범위, 형식, 가정과 성공 기준 |
| [02_research.md](02_research.md) | 기술 근거, 출처, 버전과 불확실성 |
| [03_outline.md](03_outline.md) | 개념 의존성, 설명 순서, 예제·문제 배치 |
| [04_draft.md](04_draft.md) | 전체 초고와 검증할 항목 |
| [05_review.md](05_review.md) | 기술 검증 결과와 남은 위험 |
| [06_revision.md](06_revision.md) | 구조·학습성 수정 계획과 반영 내역 |
| [07_final.md](07_final.md) | 출판 전 기준 원고 |
| [08_publish.md](08_publish.md) | 독자용 파일 경로, 변환 명령과 검수 결과 |

메타데이터는 실제 기록을 만들 때 갱신한다. `status`는 `draft`(검토 전), `reviewed`(검토 완료), `final`(해당 단계 완료)을 사용한다. 템플릿의 값을 완료 증거로 취급하지 않는다. 내부 미확인 표시는 검토에 사용하되 최종 독자용 자료에는 남기지 않는다.

## 요청 예시

```text
주제: PID 제어의 기본 원리와 튜닝
대상 독자: 미적분과 선형시스템을 아는 제어공학 입문자
학습 목표: 계단 응답을 보고 P/I/D 항을 조정한다.
분량/범위: 1장, 풀이 예제 1개와 연습문제 3개
최종 산출물 형식: 단일 Markdown
제약: 수식보다 직관적 설명을 먼저 제공한다.
```

누락 정보 처리와 기존 자료 수정 범위는 PROCESS의 시작 판단을 따른다.
