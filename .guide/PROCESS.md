# 기술자료 작성 프로세스

새 학습자료, 새 장, 대규모 개정에 적용한다. 오탈자·링크·국소적인 설명 수정은 관련 본문과 검증 기록만 갱신한다. 빌드 설정이나 에이전트 컨텍스트 유지보수에는 집필 단계를 적용하지 않는다.

파일 배치는 [OUTPUTS.md](OUTPUTS.md), 본문 표현은 [MARKDOWN_STYLE.md](MARKDOWN_STYLE.md), 단계별 기록 양식은 [템플릿 목록](README.md)을 따른다.

## 시작 판단

초고 전에 다음을 사용자 요청, 대화, 대상 책의 목차와 기존 범위 기록에서 확보한다.

- 주제와 중심 질문
- 대상 독자의 숙련도와 선행지식
- 독자가 수행할 수 있어야 할 학습 목표
- 포함·제외 범위와 분량
- 최종 산출물 형식과 경로

이미 주어진 정보는 다시 묻지 않는다. 기존 자료 수정은 기존 독자·형식·경로를 유지한다. 새 자료의 비핵심 선택은 저장소 관례에 맞게 정하고 `01_scope.md`에 가정을 기록한다. 독자·목표·범위를 크게 바꾸는 불확실성이나 기술 정확성을 좌우하는 환경 정보는 핵심 질문으로 확인한다. 답을 기다리는 동안 독립적인 조사와 현황 확인은 진행할 수 있다.

기본 형식은 여러 장이면 MkDocs 챕터형 Markdown, 짧은 단일 자료면 단일 Markdown이다. 사용자 지정 형식이 있으면 우선한다. PDF·PPTX 등 추가 변환은 요청 범위에 있을 때 수행한다.

## 집필 단계

앞 단계의 결과를 다음 단계의 입력으로 사용한다. 신규 집필은 아래 순서로 진행하고, 기존 자료 개정은 영향받는 단계부터 재검토한다. 템플릿 전체를 미리 복사하거나 빈 단계 파일을 완료 증거로 만들지 않는다.

| 단계·기록 | 수행 내용과 다음 단계 진입 조건 |
|---|---|
| `01_scope.md` 범위 | 독자·선행지식·새 개념, 하나의 중심 질문, 행동으로 표현한 목표, 포함·제외 범위, 형식·경로·성공 기준을 기록한다. 중요한 미확정 사항을 해결한 뒤 진행한다. |
| `02_research.md` 조사 | 교과서·논문·공식 문서·표준·구현체를 우선한다. 정의·수식·알고리즘·버전 의존 주장에 출처와 적용 조건을 대응시킨다. 핵심 근거를 검증하지 못하면 초고로 넘어가지 않는다. |
| `03_outline.md` 구성 | 개념 의존성과 새 용어의 첫 설명 위치를 정한다. 핵심 개념에 예제·확인 질문을, 학습 목표에 연습문제를 대응시킨다. 상태·흐름이 중요하면 그림이나 표를 계획한다. |
| `04_draft.md` 초고 | 개념·예제·문제·흔한 오류·요약을 포함해 처음부터 끝까지 읽을 수 있게 쓴다. 문장 교정보다 설명 흐름과 누락 방지를 우선한다. 불확실성은 내부 초고에 표시한다. |
| `05_review.md` 기술 검증 | 출처와 주장, 정의·용어·수식·단위·가정·알고리즘·코드·그림·표를 대조한다. 코드·계산은 가능한 범위에서 실행하고, 검증 결과와 미실행 조건·남은 위험을 구분한다. |
| `06_revision.md` 퇴고 | 필수 기술 수정을 반영한 뒤 설명 순서와 학습성을 개선한다. 풀이 예제와 직접 푸는 문제를 배치하고, 본문만으로 문제를 풀 수 있는지 확인한다. |
| `07_final.md` 기준 원고 | 문장·용어·Markdown 표기를 정리한다. 미확인 내용을 검증·수정하거나 제외하고 내부 메모를 제거한다. 학습 목표·본문·예제·문제의 대응을 확인한다. |
| `08_publish.md` 산출물 검수 | OUTPUTS에 따라 독자용 파일을 실제 생성한다. 경로와 필요한 변환 명령, 링크·수식·표·코드·그림 검수 결과를 기록한다. MkDocs 검증 명령은 [루트 README](../README.md)를 따른다. |

기술 검증 → 구조 퇴고 → 문장 교정의 순서를 지킨다. 새 용어 설명과 수식 표기의 상세 기준은 MARKDOWN_STYLE에서 확인한다.

## 기록과 재개

- 단계 기록은 기본적으로 `docs/<book-slug>/_work/`에 둔다. 장별로 기록을 분리한 기존 책은 `_work/<chapter-slug>/` 구조를 유지한다.
- 실제 의사결정, 출처, 검증 결과, 남은 작업을 기록한다. 기존 기록은 관련 부분만 읽고 갱신한다.
- 재개할 때는 대상 본문과 관련 기록의 상태를 대조한다. 오래된 초고나 `07_final.md`로 최신 독자용 본문을 덮어쓰지 않는다.
- 템플릿의 점검표와 안내 문구를 독자용 본문으로 복사하지 않는다. `_work/` 파일만 작성한 상태는 자료 작성 완료가 아니다.

## 되돌아갈 단계

| 발견한 문제 | 조치 |
|---|---|
| 독자·목표·범위 변경 | `01_scope.md`를 갱신하고 영향받는 후속 단계를 재검토 |
| 출처 부족·버전 불확실 | `02_research.md`에서 근거 확보 |
| 설명 순서·개념 의존성 오류 | `03_outline.md` 재설계 |
| 본문 누락·핵심 내용 오류 | `04_draft.md` 수정 후 `05_review.md`에서 재검증 |
| 기술 오류 발견 | `05_review.md`에 기록하고 원인 단계로 복귀 |
| 학습 목표와 예제·문제 불일치 | `06_revision.md`에서 개선 |
| 문장·표기 문제 | `07_final.md`와 해당 독자용 본문 수정 |
| 경로·렌더링·변환 문제 | `08_publish.md`에서 처리. 내용 오류면 앞 단계로 복귀 |

## 완료 기준

- 범위 기록의 목표·형식·경로와 실제 독자용 산출물이 일치한다.
- 관련 단계의 의사결정과 기술 검증 결과가 기록되어 있다. 실행하지 못한 검증은 수행한 것으로 표시하지 않는다.
- 본문·예제·연습문제가 학습 목표와 대응하고, 필요한 선행지식과 적용 조건이 설명되어 있다.
- 최종 본문에 내부 메모나 미해결 `TODO`, `검증 필요`, `출처 필요` 표시가 없다.
- [OUTPUTS.md](OUTPUTS.md)의 형식별 완료 기준을 충족하며, 수행한 빌드·변환·검수 결과와 제한을 보고한다.
