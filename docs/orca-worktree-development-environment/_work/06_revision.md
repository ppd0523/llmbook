# 퇴고 기록

## 설명 흐름

1. 1장에서 Git 작업 파일, 런타임, 다운로드 캐시, 설치 결과, 셸 선택 상태의 경계를 먼저 설명한다. Copy-on-Write는 처음 등장하는 문장에서 뜻을 덧붙인다.
2. 2장에서 Python·Node 예제를 독립 Git 저장소로 만들고 버전 요청·잠금 파일을 추적한다. 3·4장에서 같은 잠금 파일과 변경된 잠금 파일을 차례로 실습한다.
3. 5장에서 앞서 익힌 명령을 Orca setup hook에 연결한다. 한 줄 hook 명령이 추적된 짧은 스크립트를 호출하고, hook 셸의 `nvm use`가 에이전트 터미널로 이어지지 않는 점을 명시한다.
4. 6장에서 생성·런타임·캐시·설치 결과의 시간과 실패를 분리해 진단하고, 병합 후 재설치와 정리로 마무리한다.

## 학습 목표와 확인 문제

각 장에 실행 조건, 기대 결과, 직접 해보기 또는 확인 문제가 있다. 같은 잠금 파일의 오프라인 성공과 브랜치별 Rich·Chalk 차이를 본문 명령으로 확인할 수 있다. 5장의 공유 설치 결과 문제는 앞 장의 독립 환경 실습을 기준으로 판단한다.

## 기술 검토에 따른 본문 기준

- Node setup 스크립트는 `nvm.sh`를 먼저 불러온다. 새 복사본에서 실행해 확인했다.
- Orca hook의 셸·시작 경로는 문서에서 확인할 수 없으므로, 단정 대신 진단 명령과 결과 해석을 제시한다.
- 5장은 setup이 생성 시점의 절차이며 잠금 파일 변경 이후에는 다시 동기화해야 함을 설명한다.
- Orca GUI 실습 미실행, Linux·Windows 미실행은 검증 기록에 두고, 최종 본문에는 적용 조건을 표시한다.
- 로컬 도구·`.env` 문제는 패키지 캐시와 분리된 별도 층(1.2절 일곱 층의 “Git 무시 로컬 파일”)으로 다룬다. 5장은 추적 명령·작업별 복사·공통 읽기 경로의 선택 기준을, 6장은 누락·미로드 증상을 다룬다.
- 두 예제에는 무해한 `.env.example`과 추적된 `.worktreeinclude`가 있어, 일반 Git 워크트리와 Orca 생성 작업의 차이를 독자가 따라 확인할 수 있다.

교정 전 점검: 6개 장의 내부 링크, 실습 경로, 표·코드 블록의 위치가 확정됐다. 최종 본문에 내부 TODO는 없다.
