# 초고 기록

본문은 `03_outline.md`의 챕터 구조와 `05_review.md`의 판정을 기준으로 쓴다. 이 기록은 작성 분담과 챕터별 서술 기준을 남긴다.

## 1. 분담

본문 10개 챕터는 세 묶음으로 나누어 작성한다. 묶음 경계는 `03_outline.md`의 챕터 분리 근거를 따른다.

| 묶음 | 챕터 | 중심 과제 |
|---|---|---|
| 개념과 환경 | 1–3 | 도구 책임 구분, CMake·Make 조작, Flake 셸 |
| 선언과 소비 | 4–6 | Conan recipe·프로필, CMake 프로젝트, DDS 도메인 |
| 검증과 진단 | 7–10 | 네이티브 실행, 교차 빌드, 배포, 진단 |

## 2. 묶음 공통 결정

묶음마다 다르게 판단하면 책 전체가 어긋나는 항목이다.

- **6장은 5장과 7장 사이에 둔다.** 2장 뒤로 옮기면 6.3의 IDL 생성물 기록 근거가 교차 빌드 맥락을 필요로 해 그 부분만 8장으로 떼어내야 한다. 도메인 설명의 응집을 깨는 대가가 흐름 개선보다 크다. 근거는 `03_outline.md` 12절 5번과 같다.
- **확인 활동 절 이름은 "직접 확인"이다.**
- **`target`은 CMake 용어로만 쓴다.** 배포 대상 장치는 "대상 장치"로 적는다.

## 3. 묶음별 서술 기준

### 1–3장

- 1.4는 "왜 aarch64-musl 정적 링크인가"만 다루고, 정적 링크의 보장 범위와 판정은 8.5에 둔다.
- 2장은 예제 프로젝트 코드 대신 `greeting`·`hello` 최소 예제를 쓴다. 실제 프로젝트 코드는 5장만 갖는다.
- 3.1이 CMake 3.x 고정 이유의 유일한 설명 위치이고, 10.3은 진단 관점의 짧은 참조다.

### 4–6장

- `default_options` 발췌는 실제 `conanfile.py`의 9항목과 같고, `spdlog/*:header_only=False`가 `spdlog::spdlog` target 이름의 전제임을 밝힌다.
- 교차 프로필의 `compiler_executables`는 C와 C++ 컴파일러 항목을 모두 보인다.
- 5장의 configure 출력은 실제 생성 파일 기준이며, 전역 target과 component target이 서로 다른 메시지를 낸다는 점을 설명한다.
- 4.7은 개념 설명이고 `conan lock create` 실행은 7·8장에 있다.
- 6장은 두 프로그램의 명령행 인터페이스를 정리해 7장의 실행 명령이 설명 없이 읽히게 한다.

### 7–10장

- 8.4의 ELF 검사는 "명령 → 볼 것 → 기대값 → 어긋나면 의심할 것" 점검 절차로 쓴다.
- 8.5는 정적 링크의 보장 범위를 모으고, musl과 glibc를 상호 대체 관계인 libc 구현으로 서술한다.
- 9장의 네트워크 설정은 `General/Interfaces/NetworkInterface` 형태를 쓰고, 구형 옵션을 만났을 때의 대응을 함께 둔다.
- 10장 점검표에는 대상 장치 실행 실패 행이 있고, 진단 연습을 하나 둔다.

## 4. 남은 제약

이 저장소가 있는 환경에서는 Nix, Conan, CMake를 실행할 수 없고 aarch64 대상 장치도 없다. 따라서 명령 출력은 형식을 보이기 위한 예시로 다루고, 실행해야만 확인되는 항목은 단정 대신 점검 절차로 적는다. 판정 근거는 `05_review.md`에 있다.
