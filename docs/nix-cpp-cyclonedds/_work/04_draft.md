# 초고 기록

이 재집필은 완성된 본문이 이미 있는 상태에서 시작했다. 따라서 초고는 빈 문서에서 쓰지 않고, 기존 본문을 `03_outline.md`의 챕터 구조와 `05_review.md`의 판정에 맞춰 다시 쓰는 방식으로 진행했다. 이 기록은 그 작업의 분담과 판단을 남긴다.

## 1. 분담

본문 10개 챕터를 세 묶음으로 나누어 작성했다. 묶음 경계는 `03_outline.md`의 챕터 분리 근거를 따랐다.

| 묶음 | 챕터 | 중심 과제 |
|---|---|---|
| 개념과 환경 | 1–3 | 도구 책임 구분, CMake·Make 조작, Flake 셸 |
| 선언과 소비 | 4–6 | Conan recipe·프로필, CMake 프로젝트, DDS 도메인 |
| 검증과 진단 | 7–10 | 네이티브 실행, 교차 빌드, 배포, 진단 |

## 2. 집필 전에 확정한 교차 결정

묶음마다 다르게 판단하면 책 전체가 어긋나는 항목을 먼저 정했다.

- **6장의 위치를 유지한다.** `03_outline.md` 12절 5번은 6장을 2장 뒤로 옮기는 안을 제시했다. 그러나 6.3의 IDL 생성물 기록 근거가 교차 빌드 맥락을 필요로 해 그 부분만 8장으로 떼어내야 한다. 도메인 설명의 응집을 깨는 대가가 흐름 개선보다 크다고 보아 5장과 7장 사이를 유지했다.
- **확인 활동 절 이름을 "직접 확인"으로 통일한다.** 기존에는 "직접 확인"과 "연습문제"가 섞여 있었다.
- **`target`은 CMake 용어로만 쓴다.** 배포 대상 장치는 "대상 장치"로 적는다.

## 3. 묶음별 주요 변경

### 1–3장

- 1.4를 "왜 aarch64-musl 정적 링크인가"로 좁히고, 정적 링크의 보장 범위와 판정은 8.5로 넘겼다.
- 2장에서 예제 프로젝트 코드를 빼고 `greeting`·`hello` 최소 예제로 교체했다. 실제 프로젝트 코드는 5장이 단독으로 갖는다.
- 3.1을 CMake 3.x 고정 이유의 유일한 설명 위치로 삼았다. 10.3은 진단 관점의 짧은 참조로 줄였다.

### 4–6장

- `default_options` 발췌를 실제 `conanfile.py`의 9항목에 맞추고, `spdlog/*:header_only=False`가 `spdlog::spdlog` target 이름의 전제임을 밝혔다.
- 교차 프로필의 `compiler_executables`에서 잘려 있던 C 컴파일러 항목을 복원했다.
- 5장의 configure 출력을 실제 생성 파일 기준으로 교체하고, 전역 target과 component target이 서로 다른 메시지를 낸다는 점을 설명했다.
- 4.7을 개념 설명으로 줄이고 `conan lock create` 실행은 7·8장으로 모았다.
- 6장에 두 프로그램의 명령행 인터페이스 정리를 넣어 7장의 실행 명령이 설명 없이 읽히게 했다.

### 7–10장

- 8.4의 ELF 검사를 "명령 → 볼 것 → 기대값 → 어긋나면 의심할 것" 점검 절차로 바꿨다.
- 8.5에 정적 링크의 보장 범위를 모으고, musl과 glibc를 상호 대체 관계인 libc 구현으로 다시 서술했다.
- 9장의 네트워크 설정을 `General/Interfaces/NetworkInterface` 형태로 교체하고 구형 옵션 대응을 남겼다.
- 10장 점검표에 대상 장치 실행 실패 행을 추가하고 진단 연습을 하나 두었다.

## 4. 남긴 제약

이 저장소가 있는 환경에서는 Nix, Conan, CMake를 실행할 수 없고 aarch64 대상 장치도 없다. 따라서 명령 출력은 모두 형식을 보이기 위한 예시로 표시했고, 실행해야만 확인되는 항목은 단정 대신 점검 절차로 적었다. 판정 근거는 `05_review.md`에 있다.
