# 라이브 뷰와 웹캠 영상원

## 라이브 뷰는 연속 JPEG 취득이다

EDSDK의 PC 라이브 뷰는 카메라가 보내는 전자식 뷰파인더(Electronic View Finder, EVF) 이미지 데이터를
반복해서 가져오는 기능이다. `EdsDownloadEvfImage`는 이 프레임을 미리 만든 메모리
스트림에 기록하고, 앱은 스트림의 바이트와 길이를 읽어 JPEG로 표시하거나 후속 영상
파이프라인에 전달한다. 공개 API 참조서와 헤더에는 EVF 이미지 객체, 출력 장치, 확대,
초점 보조, 히스토그램, 좌표계가 별도 속성으로 정의되어 있다.
[EDSDK API Programming Reference](https://downloads.triprism.com/public/%5B%20Steve%20%5D/forTyler/canon%203.4sdk/EDSDK_API%203.4.pdf),
[공개 헤더 사례](https://github.com/samizzo/canon-tweet/blob/master/EOS%20SDK%20v2.11%20Windows/EDSDK/Header/EDSDKTypes.h)

따라서 이 기능은 HDMI 캡처 장치나 USB UVC 웹캠과 다르다.

| 경로 | EDSDK가 담당하는 범위 | 별도로 필요한 것 |
|---|---|---|
| 앱 내부 미리보기 | JPEG 프레임 취득 | JPEG 표시와 화면 갱신 |
| 브라우저 스트리밍 | JPEG 프레임 취득 | 인코딩·HTTP/WebRTC 전송·접속 제어 |
| 화상회의용 가상 웹캠 | 프레임 원본 제공 | 운영체제 가상 카메라 계층과 픽셀 형식 변환 |
| 저지연 고화질 영상 | 제어·미리보기 보조 | 보통 HDMI 캡처 등 별도 영상 입력 경로 검토 |

## 라이브 뷰 시작과 종료

1. 카메라 세션을 열고 속성 이벤트 수신기를 등록한다.
2. `kEdsPropID_Evf_OutputDevice`의 현재 값을 읽는다.
3. 기존 값의 비트를 보존한 채 PC 출력 비트(`kEdsEvfOutputDevice_PC`)를 추가해 다시 설정한다.
   화면(TFT) 출력을 덮어쓰는 것이 아니라 출력 대상에 PC를 추가하는 개념이다.
4. 속성 변경 이벤트 또는 실제 프레임 취득 성공을 기다린다.
5. 프레임마다 메모리 스트림과 EVF 이미지 객체를 만들고 `EdsDownloadEvfImage`를 요청한다.
6. 프레임의 JPEG와 부가 정보를 소비한 뒤 두 객체를 해제한다.
7. 종료할 때 현재 출력 장치 값에서 PC 비트만 제거해 다시 설정한다.

캐논의 예제는 3단계에서 PC 비트를 OR 연산으로 추가하고, 종료 때 해당 비트만 제거한다.
이는 카메라 화면 출력을 불필요하게 바꾸지 않는 중요한 규칙이다.
[EDSDK API Programming Reference, Live View 시작·종료](https://downloads.triprism.com/public/%5B%20Steve%20%5D/forTyler/canon%203.4sdk/EDSDK_API%203.4.pdf)

## 프레임 취득 루프의 규칙

| 규칙 | 이유 |
|---|---|
| 다음 프레임 요청은 이전 프레임의 스트림·EVF 객체를 처리·해제한 뒤 한다. | 객체와 메모리가 누적되는 것을 막는다. |
| 일시적 “프레임 준비 안 됨” 오류는 정상적인 재시도 후보로 다룬다. | 시작 직후와 카메라 상태 전환 중에는 즉시 프레임이 없을 수 있다. |
| 재시도는 짧은 간격·상한·중지 신호를 둔다. | 무한 바쁜 대기와 종료 지연을 막는다. |
| 표시 속도와 취득 속도를 분리한다. | 느린 브라우저·화면 때문에 카메라 제어가 멈추지 않게 한다. |
| 소비되지 않은 프레임은 쌓지 말고 최신 프레임을 우선한다. | 웹캠 미리보기의 지연이 계속 커지는 것을 막는다. |
| EVF 좌표계는 실제 프레임 취득 뒤 읽는다. | 확대·초점 위치·터치 AF 좌표 변환의 기준이 된다. |

라이브 뷰 프레임은 녹화 파일이나 무손실 센서 데이터가 아니다. 프레임률, 해상도, 지연,
색·오버레이 정보는 카메라 상태와 SDK 버전에 따라 달라질 수 있다. 웹캠 품질 요구가 있는
프로젝트는 EOS Utility로 보이는 미리보기와 EDSDK로 취득한 프레임을 각각 시험해 실제
지연과 해상도를 기록한다.

## 확대와 부가 정보

`kEdsPropID_Evf_Zoom`과 `kEdsPropID_Evf_ZoomPosition`은 라이브 뷰의 확대 비율과
확대 영역을 다룬다. `EdsEvfImageRef`에서 가져오는 초점 보조, 히스토그램, 이미지 위치,
좌표계, 확대 사각형 같은 데이터는 프레임과 같은 시점의 정보를 사용해야 한다. 이전 프레임의
AF 테두리를 다음 프레임 위에 그대로 그리면 화면과 맞지 않을 수 있다.

캐논의 현재 CAP 설명은 라이브 뷰에서 AF 위치·결과, 히스토그램, 전자 수평, 이미지 크기
변경을 포함한 표시 정보를 얻을 수 있다고 소개한다. 다만 터치 패널 전용 AF 위치 지정처럼
기종 의존인 기능도 있으므로 세 기준 기종에서 속성과 허용값으로 확인해야 한다.
[CAP Live View Monitor 기능 목록](https://asia.canon/en/campaign/developerresources/camera/cap/cap)

## 웹캠으로 쓸 때의 점검표

- 라이브 뷰가 시작된 뒤 첫 JPEG 프레임을 실제로 표시했는가?
- 프레임을 가상 웹캠 또는 브라우저가 요구하는 픽셀 형식과 시간 정보로 변환하는 별도 계층이 있는가?
- 시청자가 느린 경우 오래된 프레임을 버리고 최신 프레임을 내보내는가?
- USB 분리, 카메라 자동 종료, 라이브 뷰 종료를 감지해 영상원을 끊긴 화면으로 명확히 전환하는가?
- 카메라가 과열·배터리 저전압 상태일 때 자동으로 종료하거나 경고하는가?
