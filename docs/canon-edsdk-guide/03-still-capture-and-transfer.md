# 정지 사진 촬영과 파일 전송

## 촬영 워크플로 선택

정지 사진은 저장 위치부터 결정한다. `kEdsPropID_SaveTo`는 결과 파일을 카메라 카드,
호스트 PC, 또는 양쪽에 둘지 정하는 속성이다.

| 저장 위치 | 적합한 경우 | 반드시 처리할 일 |
|---|---|---|
| 카메라(`Camera`) | 카드에 원본을 남기고 나중에 일괄 수집 | 파일 생성 이벤트를 받아 목록을 갱신한다. 즉시 PC 전송은 선택 사항이다. |
| PC(`Host`) | 촬영 부스처럼 즉시 PC에서 검사·처리 | 호스트 저장 용량을 카메라에 알리고, 전송 요청마다 다운로드 완료 또는 취소를 통지한다. |
| 양쪽(`Both`) | 카드 백업과 즉시 처리 모두 필요 | 카드 기록과 PC 전송을 모두 기다리고, 전송 완료 처리를 빠뜨리지 않는다. |

캐논 참조서는 Host/Both일 때 카메라가 앱의 `DownloadComplete` 또는 `DownloadCancel` 처리까지
전송할 이미지 데이터를 캐시한다고 명시한다. 이 완료 처리를 누락하면 다음 촬영·전송이
막힐 수 있다.
[EDSDK API Programming Reference, SaveTo](https://downloads.triprism.com/public/%5B%20Steve%20%5D/forTyler/canon%203.4sdk/EDSDK_API%203.4.pdf)

## 촬영 전 준비 순서

1. 세션을 열고 객체·속성·상태 이벤트 수신기를 등록한다.
2. 현재 촬영 모드, AF 모드, 셔터 속도(Tv), 조리개(Av), ISO, 화이트 밸런스, 화질을 읽는다.
3. 필요한 값은 해당 속성의 허용 목록에 실제로 있는지 확인한 뒤 바꾼다. 숫자처럼 보이는
   값이라도 임의의 노출 단계값을 보내지 않는다.
4. `SaveTo`를 설정한다. Host/Both이면 호스트 저장 용량을 `EdsSetCapacity`로 알린다.
   캐논 참조서는 PC 저장을 고른 카메라에서 이 알림이 남은 촬영 가능 수 표시에 쓰일 수
   있다고 설명한다.
5. AF 촬영이면 라이브 뷰 AF 또는 셔터 반누름 단계로 초점이 완료됐는지 확인한다.
6. 촬영 요청을 보내고, 파일 전송 요청 또는 새 파일 이벤트를 기다린다.

## 셔터 명령의 두 방식

| 방식 | 의미 | 이 기준 기종에서의 권장도 |
|---|---|---|
| `TakePicture` | 한 번의 간단한 촬영 요청 | 구버전 API 참조서에서는 오래된 기종 중심의 명령으로 설명한다. 이 세 기종에서는 아래의 셔터 버튼 제어를 우선하고 실제 패키지에서 확인한다. |
| `PressShutterButton` | 셔터를 반누름·완전 누름·해제로 나눠 제어 | EOS 200D, 200D Mark II, 850D의 촬영·AF 흐름에는 이 방식을 사용한다. |

`PressShutterButton`은 상태가 유지되는 명령이다. 반누름 또는 완전 누름을 보낸 뒤에는
반드시 `Off`를 보내 해제해야 한다. 캐논 참조서도 `Halfway`와 `Completely` 상태가 계속
유지되므로 명시적으로 종료해야 한다고 설명한다. 따라서 “완전 누름 → 즉시 해제”를 하나의
원자적 동작으로 만들고, 실패·취소 때도 해제를 보장한다.
[EDSDK API Programming Reference, 셔터 버튼 제어](https://downloads.triprism.com/public/%5B%20Steve%20%5D/forTyler/canon%203.4sdk/EDSDK_API%203.4.pdf)

## PC 저장 전송의 완료 흐름

```text
촬영 요청
  → 카메라가 파일 생성
  → DirItemRequestTransfer 객체 이벤트
  → 파일 크기·이름 등 정보 확인
  → PC 파일 스트림으로 Download
  → DownloadComplete
  → 파일 객체 해제
  → 다음 촬영 허용
```

전송이 필요 없거나 로컬 저장을 사용하지 않기로 바뀌었어도, 이미 받은 전송 요청에는
`DownloadCancel`로 카메라에 결과를 알려야 한다. 파일 객체를 단순히 해제하는 것은
전송 취소 통지가 아니다.

## 촬영 부스용 운영 정책

| 상황 | 권장 정책 |
|---|---|
| 버튼을 연속 누름 | 한 장의 전송이 완료 또는 취소되기 전 다음 촬영을 큐에 넣거나 거절한다. |
| 파일명 충돌 | 카메라 파일명 대신 촬영 시각·작업 ID를 포함한 PC 저장 이름을 별도로 만든다. |
| 카드 없음 | Host 저장만 지원되는지 먼저 시험한다. 카드 백업이 필수면 촬영을 막는다. |
| 전송 중 USB 분리 | 부분 파일을 “실패”로 표시하고, 파일 객체·세션을 정리한 뒤 재연결한다. |
| 촬영은 됐는데 PC 파일 없음 | `SaveTo`, 객체 이벤트, 다운로드 완료/취소 호출, 대상 폴더 쓰기 권한을 순서대로 확인한다. |

## 장시간 노출과 연속 촬영

벌브는 `BulbStart`와 `BulbEnd`처럼 시작과 종료가 분리된 명령으로 제어한다. 캐논 참조서는
벌브 전에 UI 잠금을 요구하며, 시작 시 노출 시간 상태 이벤트가 발생한다고 설명한다. 장시간
노출 중 앱이 종료되어 셔터가 열린 채 남지 않도록, 타임아웃·취소·프로세스 종료 경로 모두에
`BulbEnd`와 UI 잠금 해제를 둔다.

연속 촬영은 카메라의 드라이브 모드와 버퍼, 저장 매체, PC 전송 속도에 제한된다. 고정 FPS를
요구하는 시스템이라면 셔터 요청 횟수가 아니라 **전송 완료 시각**을 기록해 실제 처리율을
측정한다.
