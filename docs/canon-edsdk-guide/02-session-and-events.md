# 연결 세션과 이벤트

## 세션은 카메라 제어권이다

카메라 목록에서 찾은 카메라 객체는 아직 촬영 가능한 연결이 아니다. 세션을 열어야 해당
카메라와 논리 연결이 생기며, 그 뒤에 속성 읽기·쓰기와 명령 전송을 수행한다. 작업이 끝나면
라이브 뷰를 먼저 정지하고 세션을 닫는다. 세션을 비정상 종료하면 카메라가 연결 중 상태로
남거나 다음 실행에서 열리지 않을 수 있다.

초심자가 가장 자주 놓치는 것은 **요청과 완료의 비동기성**이다. 셔터 명령의 성공은
카메라가 요청을 접수했다는 뜻일 수 있다. 사진 생성, PC 전송 요청, 속성 반영, 카메라
분리와 같은 결과는 뒤이어 이벤트로 온다.

## 세 종류의 이벤트

| 이벤트 종류 | 대표적인 변화 | 반드시 할 일 |
|---|---|---|
| 객체 이벤트 | 새 파일, 전송 요청, 볼륨·폴더·파일 변경 | 파일 객체를 수신하고 전송 또는 취소·해제를 끝낸다. |
| 속성 이벤트 | ISO, 저장 위치, EVF 출력 장치 등 속성 변경 | 해당 속성을 다시 읽어 UI와 내부 상태를 갱신한다. 라이브 뷰 시작 완료도 여기서 확인한다. |
| 상태 이벤트 | 자동 전원 꺼짐, 셧다운, 작업 상태, 오류 | 세션 복구·재연결·사용자 경고를 결정한다. |

`DirItemRequestTransfer`는 카메라에 PC로 옮길 파일이 생겼다는 객체 이벤트다. 캐논
참조서는 원격 촬영 또는 카메라 본체 촬영 뒤 이 이벤트가 발생한다고 설명한다. PC 저장을
선택했다면 이 이벤트를 전송 완료까지 처리하지 않고 방치해서는 안 된다.
[EDSDK API Programming Reference, 객체 이벤트](https://downloads.triprism.com/public/%5B%20Steve%20%5D/forTyler/canon%203.4sdk/EDSDK_API%203.4.pdf)

## 객체 수명: 전송까지가 한 단위

EDSDK의 카메라, 목록, 디렉터리 항목, 스트림, 라이브 뷰 이미지 객체는 참조 수명으로
관리된다. 아래 원칙을 지키면 장시간 촬영에서 누적 메모리와 전송 대기를 줄일 수 있다.

- 카메라 목록에서 꺼낸 카메라 객체는 목록을 해제한 뒤에도 필요하면 유지하되, 세션 종료 뒤
  해제한다.
- 이벤트로 받은 파일 객체는 전송 성공·실패·취소를 판단할 때까지 유지하고, 마지막에 해제한다.
- 매 라이브 뷰 프레임에 만든 메모리 스트림과 EVF 이미지 객체는 프레임 처리가 끝나면 해제한다.
- 예외·취소·카메라 분리 경로도 정상 경로와 같은 정리 단계를 갖게 한다.

## 안전한 상태기계

사람이 버튼을 빠르게 누르거나 USB가 빠져도 안전하려면 화면의 버튼 상태가 아래 상태와
일치해야 한다.

| 상태 | 허용 작업 | 다음 상태 |
|---|---|---|
| `검색 중` | 카메라 목록 갱신 | `선택됨`, `연결 없음` |
| `세션 열기 중` | 취소·재시도 | `준비됨`, `오류` |
| `준비됨` | 설정 변경, 사진 촬영, 라이브 뷰 시작 | `촬영 처리 중`, `라이브 뷰 중`, `오류` |
| `촬영 처리 중` | 전송 이벤트 처리, 취소 정책 | `준비됨`, `오류` |
| `라이브 뷰 중` | 프레임 취득, AF, 원격 초점 구동, 사진 촬영 | `준비됨`, `오류` |
| `정리 중` | 라이브 뷰 해제, 세션 종료, 객체 해제 | `연결 없음` |
| `오류` | 오류 표시, 정리, 재연결 | `정리 중`, `검색 중` |

“라이브 뷰 시작” 버튼을 누른 직후 곧바로 프레임 다운로드를 시작하지 않는다. PC를 EVF
출력 장치로 설정한 뒤 **속성 변경 이벤트 또는 실제 프레임 취득 성공**을 확인하고
`라이브 뷰 중`으로 전이한다. 캐논 예제도 PC 출력 장치를 설정한 뒤 속성 변경 통지가 온
후에 다운로드를 시작하도록 설명한다.
[EDSDK API Programming Reference, Live View 예시](https://downloads.triprism.com/public/%5B%20Steve%20%5D/forTyler/canon%203.4sdk/EDSDK_API%203.4.pdf)

## UI 잠금이 필요한 경우

UI 잠금은 카메라 본체 조작과 원격 작업이 충돌하지 않도록 하는 상태 명령이다. 장시간 노출
(벌브), 저장매체 삭제·포맷처럼 중간 상태가 위험한 작업에는 잠금을 고려한다. 반대로 모든
작업에 무조건 잠그면 사용자가 카메라에서 복구할 수 없고, 해제 누락이 새 장애를 만든다.

따라서 다음 원칙을 권장한다.

- 일반 촬영·라이브 뷰는 카메라 메뉴의 현재 상태를 존중하고, 필요한 설정만 바꾼다.
- 벌브 시작 전에는 UI 잠금을 사용하고, 성공·실패·취소 어느 경로에서도 해제한다.
- 파일 삭제·카드 포맷은 별도 확인 화면과 대상 식별을 둔다. 자동 촬영 워크플로에 섞지 않는다.

## 세션 오류의 첫 대응

| 증상 | 먼저 확인할 것 | 복구 순서 |
|---|---|---|
| 카메라가 목록에 없음 | 케이블, 전원, 다른 카메라 앱, USB 절전 | 다른 앱 종료 → 케이블 재연결 → 목록 새로 고침 |
| 세션 열기 실패 | 카메라가 이미 점유됨, 절전, 이전 비정상 종료 | 앱 정리 → 카메라 전원 재시작 → 새 객체로 재검색 |
| 작업 중 분리 | 케이블·전원·자동 종료 | 현재 전송·프레임을 실패 처리 → 모든 객체 정리 → 재검색 |
| 명령은 성공했는데 결과 없음 | 이벤트 미등록, 잘못된 저장 위치, 카메라 준비 안 됨 | 객체·속성 이벤트 기록 확인 → 현재 속성 재조회 → 상태기계로 복귀 |
